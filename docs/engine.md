# Судалгааны engine (`engine/`)

Engine нь Django-оос хамааралгүй. Оролт нь хоёр файл:
- `manage.py export_events <course>`-ийн CSV;
- `manage.py export_graph <course>`-ийн JSON.

Нэг config, нэг seed, нэг өгөгдлийн файл байвал үр дүн яг ижилхэн давтагдана. Энэ нь тестээр баталгаажсан.

```powershell
.venv\Scripts\python.exe manage.py export_events ds-2026 --out exports\events.csv
.venv\Scripts\python.exe manage.py export_graph  ds-2026 --out exports\graph.json
.venv\Scripts\python.exe -m engine run experiments\real.json --out results\real-001
.venv\Scripts\python.exe -m engine synth --out data\synthetic --students 60   # туршилтын өгөгдөл
```

## Протокол (удирдамжийн §7, §9)

1. Event-үүдийг `(timestamp, event_id)`-аар тогтвортой эрэмбэлнэ. Үнэлгээ хүлээгдэж буй мөрүүдийг хасаж, тоог нь `run_info.json`-д бичнэ.
2. **Хуваалт.** `temporal` нь train/val/test-ийг хугацааны нэг босгоор хуваана. `student` нь оюутнуудыг давхцуулахгүй хуваана.
3. **Сургалт.** Загвар бүр `fit(train)` алхамд зөвхөн train-ийн шошгыг харна. Val/test шошгыг өөрчлөхөд сурсан загвар өөрчлөгдөхгүй. Энэ нь тестээр баталгаажсан.
4. **Таамаглал.** `predict(data)` бүх event-ийг дарааллаар нь дахин тоглуулна. Event бүрийн хувьд эхлээд p-г тооцож, дараа нь хариултыг ажиглан оюутны төлвийг шинэчилнэ. Глобал параметр хөдлөхгүй (online evaluation). Ирээдүйн хариултыг өөрчлөхөд өмнөх таамаглал өөрчлөгдөхгүй. Энэ нь загвар бүрт тестээр баталгаажсан.
5. **Хэмжүүр.** Test дээр AUC, LogLoss, Brier, ECE, calibration bin-ууд тооцно. Accuracy болон F1-ийн босгыг validation дээр сонгоно. Оюутны түвшний bootstrap-аар 95% CI болон `reference` загвартай харьцуулсан paired ялгааг гаргана.

## Загварууд

| Нэр | Тайлбар |
|---|---|
| `global_rate` | Train дээрх нийт зөв хариултын хувь |
| `concept_rate` | Оюутны concept бүр дээрх тэгшитгэсэн (smoothed) амжилтын хувь, a_qi-ээр жинлэсэн |
| `pfa` | Performance Factors Analysis: logistic regression. Шинжүүд нь concept бүрийн өмнөх амжилт ба алдааны log тоо, хүндрэл |
| `bkt` | Concept бүрт тусдаа BKT. Параметрийг grid search-ээр train-ийн likelihood-оор сонгоно |
| `dkg` | DKG-AP. Томьёо нь `engine/dkg.py`-ийн docstring-д, удирдамжийн §5–§6-ийн анхны хувилбараар. Edge бүр **хоёр жинтэй**: W^E (нотолгооны тархалт, residual-ийн тэмдгийг дагана) ба W^T (суралцахуйн шилжилт, дадлагаас хамаарч ≥ 0) |

`"ablation": true` тохиргоо нь дараах хувилбаруудыг автоматаар нэмнэ:
- decay-гүй;
- тархалтгүй;
- тогтмол α;
- тогтмол η;
- тогтмол W;
- dynamic W × adaptive α гэсэн 2×2 харьцуулалт.

## W-ийн хэвийнжүүлэлт ба утга (2026-10-08 шийдвэр)

- **Хэвийнжүүлэлт:** `w_norm="slack"` үндсэн тохиргоо. $\bar W_{ij} = w_{ij} / (s_j + \sum_{i'} w_{i'j})$. Энд $s_j$ нь target бүрийн сурдаг "шилжилтгүй" хувь. Өмнөх `incoming` хэвийнжүүлэлт ганц орох edge-ийг үргэлж 1 болгодог тул тэр edge-ийн градиент яг 0 байв (тестээр батлагдсан).
- **Утга:** edge бүр хоёр механизмтай.
  - $m^E_j = \sum_i \alpha_{ij} \bar W^E_{ij} \delta_i$: нотолгоо. Prerequisite-ийн хариулт дараагийн concept-ийн тухай мэдээлэл өгнө.
  - $m^T_j = \kappa \sum_i \bar W^T_{ij} a_{qi} (1-k^-_j)$: шилжилт. Prerequisite-ийг дадлагажуулах нь хариултаас үл хамааран дараагийн concept-д тусална.
- **Шалтгаан:** recovery туршилт v1-д (`experiments/w_recovery.py`-ийн өмнөх хувилбар, `results/w_recovery/`) зөвхөн нотолгооны W-тэй загвар synthetic шилжилтийн edge-үүдийг **урвуу** эрэмбэлсэн (pair AUC 0.12–0.29). Учир нь нотолгооны мессеж буруу хариултын дараа сөрөг гардаг бол шилжилт үргэлж эерэг байдаг.
- Ablation: `dkg_no_evidence_propagation`, `dkg_no_transfer`, `dkg_no_graph`.

## Гаралт

| Файл | Агуулга |
|---|---|
| `metrics.json` | Загвар бүрийн val/test хэмжүүр, calibration, bootstrap CI, paired ялгаа, сурсан параметрүүд (v_i, β_i, b_i, W̄, θ, γ, η), ажилласан хугацаа |
| `predictions.csv` | Event бүрт загвар бүрийн таамаглал, хуваалтын нэр |
| `explanations.jsonl` | `explain` дээр заасан загварын test таамаглал бүрийн logit задаргаа (c, −d_q, a·v·k⁻ бүр) ба state update-ийн edge message-үүд |
| `run_info.json` | Config, өгөгдлийн SHA-256, хуваалтын хэмжээ, хассан мөр, программын хувилбарууд |

**Тайлбарын хязгаар (§8).** Logit-ийн задаргаа нь яг тооцоолсон утга бөгөөд нийлбэр нь logit-тэй таарна. Үүнийг тест шалгадаг. Харин edge message нь *төлвийн шинэчлэлтэд* оруулсан хувь нэмэр юм. Энэ нь дараагийн амжилтын магадлалд шууд оруулсан хувь нэмэр биш. Өмнөх тархалтын prediction-д үзүүлэх нөлөөг counterfactual replay-аар тусад нь үнэлнэ. Энэ нь 6-р шатны ажил.

## Synthetic өгөгдөл

`engine synth` нь мэдэгдэж буй механизмаар (суралцах, prerequisite-ээс шилжих, мартах) лог үүсгэнэ. Үүнийг engine-ийн зөв ажиллагааг шалгахад л ашиглана, судалгааны үр дүн биш. `truth.csv` файлд үүсгэгчийн жинхэнэ магадлал байгаа тул oracle-ийн дээд хязгаарыг тооцож болно.

## Мэдэгдэж буй хязгаарлалт (v1)

- DKG-д оюутны чадварын тусгай гишүүн байхгүй. Оюутнуудын ялгаа зөвхөн төлвөөр дамжиж илэрнэ.
- Сургалт нь бүтэн BPTT, full-batch Adam. Том өгөгдөл дээр удаан ажиллаж магадгүй.
- Dynamic W нь train-ийн K цонхонд λ-холих замаар хэрэгжсэн. Ĉ нь тухайн цонх хүртэлх prediction loss-оор сурдаг, W0-руу татах regularization-тай. Удирдамжийн "үе үе шинэчлэх" гэдгийн энгийн тайлбар болно.
- Олон hop тархалт хийгдээгүй. Удирдамжийн дагуу нэг hop-оор эхэлсэн.
